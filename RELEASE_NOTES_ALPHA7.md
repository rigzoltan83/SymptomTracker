# SymptomTracker 0.1.0-alpha.7

This release fixes application routing and asset handling for both
direct LAN access and reverse-proxy deployments.

## Main changes

- All application links and form actions now use Flask-generated URLs.
- Static CSS and JavaScript URLs work correctly on nested pages.
- Uploaded food and symptom image URLs use application routes.
- Redirects no longer contain hardcoded `/symptomtracker` paths.
- JavaScript API and export URLs are generated by Flask.
- Direct access works from the application root.
- Reverse-proxy deployments can use an optional `APPLICATION_PREFIX`.
- The installer keeps `APPLICATION_PREFIX` empty by default.
- Existing proxy deployments can configure a prefix such as
  `/symptomtracker`.

## Validation

The current code has been tested successfully with:

- direct LAN access;
- reverse-proxy / Tailscale access;
- main navigation pages;
- stylesheet and JavaScript loading;
- Flask template loading;
- Python syntax checks.

## Alpha status

This is still alpha software.

Do not rely on an alpha installation as the only copy of important
data.
